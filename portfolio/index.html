Sanctions Checker — EU · US · UK export-control lookup

Tool2026 · TrapAggressor / StateWatch Repository →

The problem

An investigator tracking sanctions evasion has a product description in Ukrainian, or an HS code off a customs declaration, and needs to know whether it is restricted, under which instrument, since when, and where the official text says so. By hand that means reading three legal regimes — 13 EU annexes, 3 US BIS supplements, 11 UK schedules — each with its own code format and amendment history.

Approach

The obvious design is to ask a model for the HS code. It fails in the worst available way: it returns a plausible, correctly-formatted code that does not exist, and in a compliance context a confident wrong code is a false clearance. The failure is not that the model is unreliable — it is that a generated string has no source to check it against.

So the model is never asked to produce a code. It is asked for the two-digit HS chapter, a coarse classification into 97 buckets that language models do well. Every database row in that chapter is then retrieved, and the model chooses one. Its output is a selection from rows that already exist, so a code absent from the database cannot leave the pipeline.

The answer is picked, not written

Rejected query→ model writes a code→ no source to confirm it exists
Chapter-first query→ model names a chapter→ Database · every row in chapter 39 3912.11 · Annex XXIII 3912.20 · Annex XXIII 3912.31 · Annex XXI →a real row

Nothing connects the model to the answer. The row leaves the database; the model only ever named the chapter.

How it works

A FastAPI service over a SQLite database, rebuilt from official sources by 15 EU annex parsers plus UK schedule and US BIS supplement parsers. Classification runs four tiers: an alias table of roughly 200 known products, the chapter-first LLM stage above, keyword-intersection SQL with progressive relaxation, then a rapidfuzz fallback. Every answer returns its legal basis, annex, restriction type, date enacted and a deep link into the source document. It runs without the LLM, falling back to tiers three and four, at roughly five points lower accuracy on ambiguous queries.

Result

96.8%classifier accuracy, 125-query Ukrainian-and-English test set

Over 7,676 active sanctions entries — EU 2,332 · US 2,797 · UK 2,547. Roughly 7,300 lines of Python; 64 pytest tests across 3 modules, plus 5 accuracy harnesses that are how the 96.8% was measured, versioned so the number can be re-run rather than trusted.

Corpus Editor — Telegram video pipeline

Tool2026 Repository →

The problem

A few hundred short videos scraped from Telegram are too many to watch and too unstructured to grep. Filenames and timestamps say nothing about what is in the footage, and nothing about which clips resemble each other.

Approach

Reduce every video to a vector, then let similarity do the organising — project the vectors into three dimensions and compute nearest-neighbour edges, so visually similar material sits together and the corpus can be traversed rather than searched.

The second decision matters more in practice: both expensive stages are resumable. Downloaded files are skipped on re-scrape and embedded nodes on re-process. At corpus scale a failure 80% into a run should cost the remaining 20%, not the whole run.

It began as a tool for a film project, not an intelligence one. It is here because the pipeline underneath is the same one a media-monitoring system needs, and I would rather show one I built end to end.

Querying 77k sanctions entities — SQL and an agent

Tool2026 Repository →

The problem

The consolidated sanctions corpus is large enough that ad-hoc questions are slow to answer and easy to answer wrongly. A natural-language layer over it is obviously attractive — and the interesting question is not whether it can be built but whether its answers can be trusted without checking the work.

Approach

Build both paths and compare them rather than assuming. One is a manual-context model: I pull data with SQL and hand the result over as text, controlling exactly what the model sees. The other is a tool-calling agent that writes its own SQL. Local models could not do tool calling reliably, so that path runs on Groq while the manual path runs on local Ollama.

How it works

A Dockerised MindsDB instance sits over the OpenSanctions consolidated dataset loaded as a table, exposing both a SQL surface and an agent surface against the same rows. Full setup from a clean machine — Docker, MindsDB, Ollama, model pull, data load and every SQL statement — is documented in the repository.

MindsDBDockerOllama gemma3:4bGroq APISQLOpenSanctions

Result

76,996 entities queryable both ways — and a documented auditability failure.

"How many sanctioned entities are from Russia?"

agent 21,210
direct SQL 19,238

1,972 records unexplainedthe agent never surfaced the query it generated

The gap is not the problem — the missing query is. Both numbers are defensible; only one is auditable.

The difference is almost certainly multi-country records like ru;ua — but that is a reconstruction after the fact. There was no way to establish which question the agent had answered without redoing the work it was meant to save. For sanctions screening that is disqualifying on its own terms: a number without its query is an assertion, not a finding. The fix is that the agent surfaces generated SQL with every answer, and the answer is a draft until that SQL has been read.

A second observation from the same session: the second-largest country group in the dataset is NULL. For anyone filtering on jurisdiction, that is a silent hole in coverage rather than an empty category.

Measuring LLM fabrication rate in OSINT profiling

Method2026 Repository →

The problem

Analysts use language models to profile people, and everyone names hallucination as the risk. Nobody had a number for it on this kind of task — and without a number there is no way to tell whether prompt discipline actually changes the outcome or merely changes the tone.

Approach

Run the same profiling task twice and vary exactly one thing. Same model, same subject, and search explicitly disabled on both sides — that last part matters, because my first attempt compared a tool with retrieval against one without and was therefore not a prompt comparison at all. Then extract every discrete claim and check them one at a time.

How it works

Twelve claims were extracted from the unconstrained output and each scored true, hallucinated, unverifiable or partial, with the basis recorded per claim against three independent source families. "Unverifiable" is kept as its own category rather than folded into true or false, because collapsing it in either direction is precisely how unsourced claims enter finished analysis.

Unconstrained prompt · 12 claims

4 unverifiable
2 fabricated
6 confirmed or partial

Source-constrained, same task — nothing fabricated, nothing unverifiable

The unverifiable band is the heaviest element because it is the argument: a fabrication can be caught by checking, an unfalsifiable claim cannot be checked at all.

Result

17% → 0%explicit hallucination, unconstrained against source-constrained prompt on the identical task. Unverifiable claims fell from 33% to none

What moved the number was not the persona framing or the tone instruction but two clauses — use only facts explicitly present in the text and if a field is absent, return null — which change the model's implicit objective from producing a complete-looking profile to reporting what the source supports.

The most instructive error was not the fabrication rate. The model placed the subject at the wrong university, and the university it named is a real institution in the same city: locally plausible, superficially correct, invisible without a deliberate check. A prompt-injection test alongside was detected and refused unprompted — a narrower result than "models are safe", since one passing test on one model is not a control.

Scope and limits

Sample
One subject, twelve claims. An order-of-magnitude signal about a failure mode, not a benchmark — the method transfers, the exact numbers do not
Subject
Anonymised: a serving regional official in Ukraine. Identifying source URLs removed; source types named so the method stays reproducible
Scoring
"Unverified" means no public source was located either way
Reproduction
Model versions were not pinned at the time of the run

Russia Context Platform

Research · unfinished2026

The problem

Detecting a synthetic persona means knowing what a convincing one would have to get right. That list is not published anywhere. Detection work consequently runs on intuition about which signals are hard to fake — and intuition is a poor basis for deciding where to spend a detector's attention.

Approach

Build the substrate for a single Russian settlement and see how far it gets. Collect the local Telegram channels, regional RSS and VK material for that one place, then synthesise a place profile from it: local geography, institutions, transport, prices, seasonal rhythms, recurring names, register and dialect — deep enough that a generated resident would be hard for an actual resident to catch out.

Working at settlement scale rather than national scale is the point. National context is abundant and cheap; it is the local, unrecorded texture that is expensive, and expense is exactly what a detector wants to test.

How it works

A collection layer pulls from regional sources on a schedule and normalises what comes back. Synthesis runs over that corpus into a structured place profile. The primary store is a wiki rather than a database — a deliberate choice: the material is mostly prose with citations, it is edited by hand as often as by machine, and a wiki keeps provenance and revision attached to each claim in a way a schema does not. A knowledge graph sits alongside it for entities and relations, with a map layer for the geographic material. Models run locally, since the corpus is regional-language material that does not need to leave the machine.

It is unfinished. Collection and the wiki store work; the graph is partial, the map layer is early, and synthesis has been run over a small number of settlements rather than at any scale.

Result

5 signal classes, ranked by how hard each turned out to fabricate — which is the output that transfers to detection.

What must be faked · what a detector must check

Signal classDetection surface
Place knowledge→detail finer than public maps carry
Temporal habits→posting rhythm against local hours
Dialect, register→lexis against regional corpora
Social graph→age and reciprocity of ties, not their count
Event memory→recall of what no source ever wrote down

The first four are approximable from collected material. Event memory is not — which makes it the cheapest thing for a defender to test and the most expensive for an adversary to sustain.

The four upper classes turned out tractable: enough local geography, rhythm, lexis and plausible social structure can be assembled from open regional sources to survive casual review. Event memory did not. A profile built from sources can only contain what a source recorded, and the unrecorded local event — the thing everyone in a town knows and nobody wrote down — has no substitute in the corpus.

For detection that inverts the usual priority. Effort is better spent probing for recall of unrecorded specifics than on stylometry or posting-time analysis, and coherence across classes matters more than any single anomaly. It also sets a realistic ceiling: a detector built on the assumption of sloppy synthesis will not catch competent synthesis, and competent synthesis is achievable with open sources.

Unfinished and not open-sourced. There is no repository, no code, no screenshots and no operational parameters here, and there will not be.

Passwork — an FSB-licensed password manager in EU government systems

Investigation17 July 2026 StateWatch → OCCRP →

The question

Passwork is a password manager. It presents as a European company, and it is installed inside European public-sector organisations — the software that holds the credentials to everything else those organisations run.

The question was whether the corporate reality behind the product matched the marketing. A password manager is an unusually consequential place for that gap to exist: the product's entire function is custody of the keys.

Method

Corporate records across jurisdictions, tracing the entity structure back from the European presentation to its origin. Russian cryptographic and technical licensing registries, which are public and which record both the licence and its date. The product's own update infrastructure. Published client lists, cross-checked against sanctions designations in both directions — European public bodies on one side, designated Russian entities on the other. Technical examination of the installed software by an independent specialist. And approaches to the company for comment, which produced an on-record denial worth publishing alongside the findings.

A cross-border effort: OCCRP journalists and StateWatch, with a consortium of European outlets. My role was contributing research.

Finding

The product shares origins and update infrastructure with a Russian legal entity. That entity holds an FSB cryptographic licence obtained in 2025, and FSTEC licences from 2024 covering information-security software for state-owned enterprises. The corporate presentation had moved through a Spanish entity while the Russian company was acquiring exactly those permissions.

Its published client list ran in both directions at once. On one side, 5 named European public institutions — Germany's federal research ministry, the Government of Ireland, the Hildesheim District Administration, the University of Zurich and TU Dresden. On the other, 4 sanctioned Russian companies: Gazprom Neft, Aeroflot, Metrovagonmash and Rusal.

An independent technical examination added a mechanism to the paper trail. On installation the software contacts an external server and receives a unique identifier, transmitting the client's IP address and organisation details — which means every installation is individually identifiable to the vendor.

The company's European CEO told OCCRP there are no corporate, contractual, operational, infrastructure or data-sharing relationships between the European and Russian entities.

Why it matters

An FSB licence is not only a permission, it is an obligation. Under Russian law a licensed operator can be compelled to provide access to data in its possession — through Government Resolution 313, Federal Law 144-FZ on operational-search activities, Federal Law 149-FZ on information, and the SORM and Yarovaya framework that compels disclosure of metadata, content and encryption keys.

That makes the exposure structural rather than incidental. It does not depend on a breach having occurred, on anyone acting in bad faith, or on the denial being untrue. A sanctions lawyer quoted in the investigation put the risk in terms of legal mechanism and de facto state coercion rather than misconduct.

The framing the investigation lands on is the durable one: the question is not whether passwords have already been accessed, but who holds the keys. That is a systemic-risk argument, and it is the harder kind to make — it survives the absence of an incident, which is precisely when procurement decisions actually get taken.

The UK has designated none of them

Analysis2026 Standalone version →

The question

Sanctions policy has tracked hardware — components, microelectronics, supply chains — because goods are legible to a goods-based regime. The developer layer writing the targeting, recognition, monitoring and censorship software has been tracked much less.

How much less, and where exactly are the holes? Sanctioning a drone manufacturer while leaving the company that supplies its autonomous targeting stack undesignated addresses the airframe and not the software that makes it autonomous.

Method

97 entities identified from Russian-language open sources: company product documentation, state and state-adjacent media reporting on capability deployment, procurement and contract records, technology-park and accelerator residency lists, university laboratory pages, and investigative reporting by independent Russian and international outlets. Inclusion requires a sourced link between the entity and a military, surveillance or information-control application — not merely that the entity works on AI in Russia.

Each record carries the legal name in three languages, a functional classification, the registry number (OGRN), the tax number (INN), the registered address in three languages, a sourced designation justification with supporting URLs, and an explicit listed / not-listed status for each of the four jurisdictions.

Recording OGRN and INN rather than names alone is the load-bearing decision. Russian corporate names are unstable, frequently duplicated and routinely re-registered; a registration number survives renaming and is what makes an entity matchable against a sanctions list, a procurement record or a corporate registry. Trilingual fields exist so a record can be handed to a Ukrainian, EU or US counterpart and used without re-derivation.

Sanctions status was checked per entity against each regime's published lists and recorded as an explicit binary. No jurisdiction is inferred from another. The empty cells are as deliberate as the filled ones — a blank is a checked negative, not an unchecked field, which is what allows the gap to be counted rather than estimated.

Finding

Every track is all 97 entities, so the unfilled portion is the shortfall without arithmetic.

Three further figures define the gap. 62% — 60 of 97 — carry no Western designation at all, not US, not EU, not UK. 41% carry no designation in any of the four jurisdictions, including Ukraine's. And 20 entities are Ukraine-listed with no Western follow-through: already assessed as contributing to the war effort by the state fighting it, and untouched by any Western regime.

The finding is not that these entities are unknown. Ukraine has designated 47 of them and the justification for each is publicly sourced. The finding is that Western designation is not following, and that in one jurisdiction it has not started.

Why it matters

A zero is a different kind of number from a low number. US and EU coverage at 32% and 22% describes a regime that is engaging with this sector and has reached part of it — partial, lagging, but present. A zero describes a sector that has not been engaged at all.

The UK maintains an extensive Russia regime under the Russia (Sanctions) (EU Exit) Regulations 2019, including detailed goods-based export controls across 11 schedules. The absence is therefore not a matter of lacking a regime or lacking instruments. It is that the military-AI developer layer specifically has not been brought inside them.

Microelectronics is the best covered at 42% undesignated — unsurprising, since component supply chains have been the primary focus of export-control policy since 2022. Hardware is legible to a regime built around goods. Computer vision is the worst at 77%: thirteen entities, one US listing, two EU, none UK. And the universities and state funds sit at 67% and 64% — these are the pipeline, the institutions producing the researchers and directing the money. They are harder to designate, for real reasons of academic freedom and proportionality, but the effect of leaving them out is that the sector's inputs stay untouched while its outputs are sanctioned one company at a time.

The counter-disinformation cut

Fifteen entities develop media monitoring, censorship and cyber-operations tooling. This is the cluster that matters to anyone working on information operations, because these are the systems that detect, characterise and act on the information environment inside Russia — and increasingly on its perimeter. US coverage is comparatively strong here at 7 of 15, its best ratio of any cluster; the EU's is 2, Ukraine's is 4, the UK's is zero.

The functional profile is consistent across the cluster: social-media and mass-media monitoring platforms, sentiment and author analysis, automated detection of undesirable content, and threat-intelligence tooling sold to state customers. Several are marketed openly to government buyers with public-sector client lists. At least one claims publicly to forecast public reaction to state initiatives and to identify and "work with" difficult authors and opinion leaders.

That last capability is worth stating plainly, because it is the point at which a media-monitoring product stops being analytics: identifying influential critics and routing them to an intervention is the operational core of an information-control system, and it is sold as a commercial feature. The technical distance between "detect undesirable content at national scale" and the detection systems a counter-disinformation vendor builds is small. The difference is entirely in who points it and at whom.

What follows

The twenty Ukraine-listed entities with no Western follow-through are the lowest-friction candidates for alignment, because the identification and evidentiary work is already done and published. Coverage is weakest in the software layers and in the institutions feeding them, and best in hardware — which is a statement about what the instruments were designed to reach, not about where capability sits.

Published here: the finding, the cluster taxonomy, the record schema and — in the standalone version — three fully worked example entries, drawn only from entities already under public designation, so nothing is disclosed that is not already a published listing. The 97-entity dataset itself is held privately. Full dataset available on request.

Pro-Russian information network in Moldova

AnalysisMay 2026 Repository →

The question

Within a fixed perimeter of 28 Telegram channels pushing pro-Russian and anti-Western content in Moldova, does the observable structure look organic — or does it show coordination?

The perimeter was defined in advance, which bounds every claim that follows: this describes structure inside a boundary, not a network discovered from scratch. Channels outside the list appear only as citation targets.

Method

A batch script drove GroupInt across every target — 500 messages each, then endorsement extraction, with a five-second delay between channels to stay under Telegram's flood-wait threshold and per-channel failures logged and skipped rather than aborting the run. Everything landed in a Neo4j graph: Group, Message and User nodes, with ENDORSES edges parsed from @username and t.me/ links in message text.

In- and out-degree were computed in Cypher. The GDS plugin was unavailable, so there is no betweenness and no algorithmic community detection — the clusters are an analyst's reading of content and endorsement direction, and the report says so rather than implying a computed result.

Finding

27 channels indexed of 28 targeted — one was not resolvable on Telegram. 23,110 messages, 424 endorsement links across 164 unique channel pairs, 4 clusters.

83 in · 8 out@primulinmd — the one node cited by all three narrative pipelines. KP Moldova is the mirror: 129 out, 0 in

The structural finding. @primulinmd receives 83 endorsements and sends 8. It is the single node receiving citations from all three narrative pipelines. KP Moldova is the mirror image: out-degree 129, in-degree zero — the busiest distributor in the network, and nothing comes back to it.

Four clusters. A central anti-Sandu hub built around KP Moldova and primulinmd, focused on domestic politics in a register critical of the president and the governing party. A Transnistrian cluster — e_tiraspol, pridnestrovec, np_inform — hyper-focused on local PMR news and citing official Transnistrian structures. A Gagauz cluster promoting the region as a pro-Russian island of stability. And an external bridge, led by Balkan-Centre at out-degree 41, moving content between the Moldovan segment and the wider post-Soviet and Balkan space.

Four patterns, weighted separately rather than collapsed.

Copy-paste pairs. @e_tiraspol and @pridnestrovec published six or more byte-identical texts on matching dates — weather bulletins, notices about Russian-passport queues, hot-water outage announcements, school heating restored. The duplication is systematic, not occasional.

Concentrated citation. The 83 endorsements of @primulinmd arrive from five different channels across three ideologically distinct clusters — KP Moldova 59, Mamalyga i Tokana 9, Gagauznews 7, Moldavskaya politika 6, e_tiraspol 1. Cross-cluster agreement on a single authority is not what organically formed media networks look like.

Synchronised framing. On 27 May 2026 at least four channels published the Moldovan Security Council's decision to raise gas VAT from 8% to 20%, within hours of each other and in near-identical wording — framed not as fiscal policy but as proof of betrayal.

Shared external diet. Across the 424 endorsements, channels from unconnected clusters cite the same narrow set of external channels, the most-cited appearing 26, 25 and 21 times respectively.

Why it matters

A channel cited by ideologically distinct clusters that cites almost nobody in return is the network's shared authority. That degree asymmetry is a structural signature: it does not depend on reading the content, which makes it cheap to compute, language-independent, and hard to disguise without giving up the coordination it enables.

The network functions as three parallel narrative pipelines — Transnistrian legitimacy, anti-Sandu delegitimisation, and Gagauz separatism — joined at a single amplifier. That topology is the useful output, because it says where a monitoring effort should watch and what a takedown would and would not disrupt.

The honest limit belongs with the finding. Identical text and synchronised timing are consistent with coordination between administrators, and equally consistent with a shared press-service feed. The report says which is which for each pattern rather than collapsing them into a single claim of proof.

ZhBK-185

Sample reportJune 2026 Standalone version →

The question

ZhBK-185 produces anti-tank obstacles — dragon's teeth — in occupied Zaporizhzhia oblast, at sites in Berdiansk and Melitopol. Those are not new-build factories. They are Ukrainian reinforced-concrete plants that existed before the occupation and were taken over.

Which Ukrainian companies and facilities were captured; is the management of the successor operation connected to the original companies; what else is the operation linked to; and what can be established about its finances.

Method

Identify the pre-war entity from Ukrainian registry data and pre-war corporate directories. Then find the successor in Russian registries by physical address rather than by name — the address survives the renaming — and compare directorships across the two systems.

Names change, corporate forms change, jurisdictions change. Addresses and registry numbers persist, and people are lazier than they are careful.

Finding

Two plants captured under two different patterns, a network of five linked legal entities, and management continuity across the seizure at both sites.

Melitopol. The pre-occupation entity was a Ukrainian private joint-stock reinforced-concrete plant. After the occupation the asset split along the front line: the Ukrainian legal entity was re-registered inside the Ukrainian system, while a new Russian company was incorporated — and it is the Russian entity that actually operates the plant under the ZhBK-185 brand. Its INN prefix falls in the range allocated to entities registered in the occupied territories, so the number encodes the circumstances of its own creation.

Berdiansk. A different pattern. The pre-war operator was a Ukrainian company at a known street address; after the occupation, Russian-registered entities took over operations at that same address. The address is the pivot — searching Russian registries for the original plant address surfaces the current occupant.

Management continuity is the substantive finding. At Melitopol, the person who was the long-standing director of the pre-war Ukrainian company is now general director of the Russian successor, appointed June 2023, holding a founder's stake of ~20.5%. The plant did not merely change hands: its management stayed in place and acquired equity in the Russian vehicle that took it.

At Berdiansk, pre-war ownership was linked to the family of a Ukrainian MP. The current director of the Russian entity operating at the original plant address is a former deputy mayor of the city and a known political associate of that same MP. The pre-war political network around the asset is the network now running it. That entity also uses a corporate email on the domain of the group operating the site — a small artefact, and one of the harder links in the chain, because an operational address is chosen for convenience rather than cover.

The network. ZhBK-185 is not a company but a brand across several legal entities: the Melitopol operator, the main Berdiansk operator and two affiliates, and a separate entity that appears as the billing arm on the brand's own public contact page. Two of these were found by different routes worth naming because they generalise — one surfaces on an address search of Russian registries, the other is published by the operation itself.

Finances. There is no consolidated figure, because the brand is a network rather than a legal entity. The correct answer is to decline the estimate and report per-entity registry figures instead. One caveat materially limits what the Berdiansk operator's accounts can be made to say: its primary activity code is wholesale trade in fuels, and the plant is one of some seventy declared activity areas, so its revenue cannot be attributed to fortification production.

Citizenship. Of four individuals in directing or founding roles across the network, three hold Ukrainian citizenship and one is Russian. One individual's Russian tax number carries an issuing-region prefix outside the occupied territories — a tax number encodes where it was issued, which can date and place a person's entry into the Russian administrative system rather than merely establishing that they entered it.

Why it matters

Continuity changes what the case is. A plant seized and run by outside operators is expropriation. A plant whose management stayed in place and took equity in the vehicle that acquired it is collaboration, with a documented ownership interest attached — a materially different fact for any designation or prosecution built on it.

The method generalises to any occupied-asset case: pre-war entity, successor by address, then check whether the people are the same. It works because operational convenience beats operational security — the successor keeps the address, and often the email domain.

It also demonstrates where to stop. "Provide financial data for ZhBK-185" is unanswerable as put, and the useful response is to say why and report what the registries actually support, rather than producing a number that would look like an answer.

Individuals are anonymised by role throughout. Corporate registry identifiers are retained in the standalone version: companies operating in occupied territory are legitimate subjects of open-source research, and the registry numbers are the evidence. Personal-profile links have been removed.

Economies of the Aftermath

InvestigationAnti-War Coalition Journal Published version →

The question

Mariupol is routinely described as a city awaiting reconstruction. That framing carries an assumption: that destruction is an interruption in an economy which will resume, and that the fragments can be reassembled into the thing they were.

The question is what happens if that assumption is dropped — if the destruction is read not as an interruption but as a precondition, and the economy that follows is examined on its own terms rather than as a damaged version of the previous one.

Method

The piece works from the physical record rather than from testimony alone, and from the grid rather than from buildings. Transmission lines and substations are large, fixed and identifiable from above, which makes them a harder evidentiary base than damage counts of housing stock — and, unlike housing, they determine what an economy can physically do afterwards.

Satellite imagery assessment of the city's energy infrastructure and of distribution points, read alongside the sequence of the first weeks: what was destroyed, in what order, and what that ordering permitted. The methodological frame the piece names for this is negative archaeology — inferring from absences, on the principle that the absence of evidence is not evidence of absence.

Finding

All 15 of the city's electricity lines were destroyed by 2 March 2022. 16 substations at 330/220/110 kV were assessed — the two major nodes plus at least fourteen 110 kV substations. Internet connectivity fell to 7% of normal over the same period. Water treatment depended on one of the destroyed substations, which is how a power target becomes a water outage.

The pattern extends to distribution. Of 11 announced bread distribution points, satellite imagery shows at least 3 sustained damage by 14 March, with further hits over the following fortnight. Queues at functioning stores reached 300 people.

What replaced the formal economy is legible in its pricing. Currency gave way to barter indexed to fuel: two hours of phone charging for one litre of A92, eight hours of power-bank charging for four. Shelter micro-economies formed with assigned roles — guards, sanitation, cooking, medicine-sharing — at the scale of a single basement.

Then the occupation economy arrives with its own instruments. A Free Economic Zone. Compulsory re-registration of businesses from Ukrainian to Russian corporate forms. Property claims made contingent on taking a Russian passport. And in the 2024 Russian budget, 430+ billion roubles allocated across the occupied territories — Donetsk 137.4, Crimea 126.7, Luhansk 92.5, Zaporizhzhia 60.1, Kherson 33.2.

Why it matters

The apparent paradox — a territory simultaneously subsidised and extracted from — dissolves once the arrangement is read as colonial rather than reconstructive. Systematic infrastructure destruction manufactures dependency; selective restoration of service is then the instrument through which control is exercised, alongside property expropriation and forced naturalisation.

Reading such an economy as an architecture of gaps rather than as a site awaiting reconstruction is not a rhetorical preference, because the two readings ask different questions. A site awaiting reconstruction invites asking when rebuilding starts. An architecture of gaps invites asking who the gaps are for.

Grid capacity is where that question becomes answerable, which is why the substations are the right evidentiary object: whoever rebuilds them decides what the city can produce, and for whom.

At the break: Territorialization of Arctic

Investigationroflflfl.github.io Published version →

The question

Accelerating ice loss is usually reported as an environmental story. It is also an access story: as the ice retreats, parts of the Arctic become physically reachable that were not before, and reachability is the precondition for control.

How does Russia convert that new access into infrastructure, and is the process visible from open sources?

Method

Open-source infrastructure analysis across four case studies, chosen deliberately to sit in four different domains — extraction, shipping, communications and military presence — so that a common pattern across them could not be an artefact of looking at one kind of asset.

Finding

4 case studies describing 1 process. The Prirazlomnaya platform, the first extraction installation on the Arctic shelf. The North Sea Passage. A transarctic fibre-optic cable under development for Arctic conditions. And military expansion along the northern border.

Each layer is separately visible in open sources — which is what makes the whole traceable without privileged access, and is the methodological point as much as the finding.

Why it matters

Extraction, shipping route, data cable and garrison are four layers of a single claim, and the direction of that claim is a reorientation of the Arctic's spatial and economic networks toward East Asia.

Read one layer at a time, each looks like ordinary regional development. Read together they are a territorial strategy — which is the argument for infrastructure analysis over incident reporting whenever the subject is a slow process rather than an event.
